# Album-art border trim (MenuView.swift, ArtCache.trimmedBorder)
- Pure pixel scan on the decoded thumbnail (no Vision): album art only (`trimBorder: isAlbumArt` through CachedArt / prefetch / image / thumbnail). Channel logos never trimmed.
- Rules: flat band from each edge (1% stray px, tolerance 28/255) may hold a title sliver, may be followed by a thin (<= 1/12) band of another colour (double border); ends at a line >= 50% another colour. Depth 0 if the band gave way gradually (horse on flat bg → no crop); `limit` (30%) if never ended → no crop. Pairs (top/bottom, left/right) must match colour and be within max(3, limit/5) in depth; each side crops its own depth + 1. Lines judged over the middle 70%.
- Test harness: /tmp/trim/trim.swift (runs over ~/Library/Caches/com.starplayrx.mac/ArtCache/fsCachedData, map via Cache.db → /tmp/trim/map.tsv; akamaized = Xtra track art, imgsrv = channel tiles), writes /tmp/trim/sheet.png (large/medium/tiny, BEFORE|AFTER). probe.swift / probe2.swift dump edge stats / ASCII art for one file. /tmp is wiped between sessions.
- v3 (5d72d91): user showed BEFORE|AFTER pairs where a frame was cropped on one axis only (Jimmy Eat World white frame, Grateful Dead orange frame with clipped title). Fixes: inside an inner band the "gave way gradually" rule returns bandStart (the inner band was the picture) instead of 0; a bold title in the band (edge, then the band colour back within 2*thin) continues the band; opposite-side colour tolerance 40 (sides drift under JPEG); full frame (all 4 sides same colour) only needs each axis within limit/3 (title side deeper), letterbox axis alone still limit/5. Grateful Dead now crops to the picture (title in the frame goes, same policy as Steel Pulse).
- User feedback so far: v1 overshot a horse on a flat bg (fixed), v2 missed Steel Pulse (gray frame with title text + double border; fixed). Open question (unanswered): deep (>20%) white frame with a small centred picture + text gets zoomed 2.3x and loses the text.
